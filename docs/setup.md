# Bare-Metal / VM Setup Guide

End-to-end guide for running nixtune on a standard NixOS installation
(bare-metal or virtual machine), including disk encryption and FIDO2 key
configuration.

For WSL2-specific instructions, see [wsl-setup.md](wsl-setup.md) instead.

## Prerequisites

- A working [NixOS](https://nixos.org/manual/nixos/stable/#sec-installation)
  installation with flakes enabled
- A FIDO2 security key (e.g. YubiKey)
- `sudo` / root access on the machine
- An Entra ID account with Intune enrollment permissions

---

## 1. Enable flakes (if not already)

Add the following to your NixOS configuration if you haven't already enabled
flakes:

```nix
nix.settings.experimental-features = [ "nix-command" "flakes" ];
```

Rebuild and switch so that the `nix` CLI supports flake commands:

```bash
sudo nixos-rebuild switch
```

---

## 2. Create your flake configuration

Create a flake that imports nixtune. Replace `myhost` with your hostname and
`myuser` / `myuser@microsoft.com` with your local and Entra ID usernames:

```nix
# flake.nix
{
  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";

    nixtune = {
      url = "github:yuzhoumo/nixtune";
      inputs.nixpkgs.follows = "nixpkgs";
    };
  };

  outputs = { nixpkgs, nixtune, ... }: {
    nixosConfigurations.myhost = nixpkgs.lib.nixosSystem {
      system = "x86_64-linux";
      modules = [
        ./hardware-configuration.nix  # generated by nixos-generate-config
        nixtune.nixosModules.default
        {
          networking.hostName = "myhost";
          system.stateVersion = "24.11";

          # Create your local user
          users.users.myuser = {
            isNormalUser = true;
            extraGroups = [ "wheel" ];
          };

          # nixtune config
          modules.nixtune = {
            localUser = "myuser";
            entraUser = "myuser@microsoft.com";
            wsl = false;  # bare-metal / VM
          };
        }
      ];
    };
  };
}
```

Apply the configuration:

```bash
sudo nixos-rebuild switch --flake .#myhost
```

## 3. Disk Encryption (LUKS)

The MSIT Intune compliance policy checks for a non-empty `/etc/crypttab`.
On bare-metal and VM installations, you should use full-disk encryption with
LUKS to satisfy this requirement.

### Install NixOS with LUKS from the start

The easiest approach is to set up LUKS during initial NixOS installation. The
NixOS manual covers this in detail:
[Full Disk Encryption](https://nixos.wiki/wiki/Full_Disk_Encryption).

If NixOS was already installed with LUKS, verify that `/etc/crypttab` is
populated:

```bash
cat /etc/crypttab
```

You should see at least one entry. If the file is empty or missing, ensure your
LUKS device is declared in your NixOS config under `boot.initrd.luks.devices`.

---

## 4. Enroll in Intune

With the configuration applied, disk encrypted, and FIDO2 key working, enroll
the device:

```bash
sudo aad-tool auth-test --name myuser@microsoft.com
```

- When prompted for a Hello PIN, set it to the **same password** as your local
  NixOS user. This enables automatic unseal of Entra broker secrets on login
  (via the `try_unseal` PAM rule).
- Authenticate with your FIDO2 key when prompted.

### Verify enrollment

Check that your device appears at:
https://portal.manage-beta.microsoft.com/devices

---

## 5. Post-Enrollment

After successful enrollment:

- **Compliance policies** are enforced by `himmelblaud-tasks`, which runs as a
  systemd service. You can check its status with:

  ```bash
  systemctl status himmelblaud-tasks
  ```

- **Policy scripts** installed by Intune are placed in `/etc/cron.d/` and run
  via the cron service that nixtune enables.

- **To re-enroll** (e.g. after a tenant change), remove the enrollment state
  and run the auth-test command again:

  ```bash
  sudo rm -rf /var/lib/himmelblau/
  sudo aad-tool auth-test --name myuser@microsoft.com
  ```
